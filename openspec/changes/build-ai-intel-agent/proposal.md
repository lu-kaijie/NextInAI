## 背景

AI 领域的信息密度和更新速度极高，单靠手动刷 GitHub、公司博客、论坛和报告很难持续跟上，也难以及时判断哪些更新真正值得关注。现在需要一个以 Python 为核心的 AI Agent，自动完成采集、筛选、解读、汇总与通知，让用户既能主动查询，也能被动接收高价值情报。

## 变更内容

- 新建一个面向 AI 信息追踪的 Python Agent 项目，覆盖从数据采集、分析到通知交付的基础闭环。
- 第一版以 CLI 为主要使用入口，支持用户主动查询、生成报告并下载 Markdown 与 PDF 格式结果。
- 支持订阅指定 GitHub 仓库，跟踪一段时间内的发布、提交、PR 合并和文档更新，并生成“更新了什么”的结构化摘要。
- 支持发现某日或某时间段内热门的 GitHub 项目，重点输出排行榜项目是做什么的、为何上榜以及是否值得继续关注。
- 支持采集 AI 公司、研究组织和论坛发布的报告或公告，并生成面向非原文阅读者的解读摘要。
- 提供报告生成与通知系统，支持用户主动触发查询，以及按计划通过邮件和 Webhook 定期推送简报。
- 为后续多源扩展预留能力，包括新增内容源、新增通知渠道和更细粒度的用户偏好配置。

## 能力范围

### 新增能力
- `github-subscription-tracking`: 订阅并追踪指定 GitHub 仓库的近期更新，输出结构化变化摘要与解读。
- `github-trend-analysis`: 识别某日或某时间窗口内热门的 GitHub 项目，并生成项目介绍与热度解读。
- `ai-report-interpretation`: 汇总 AI 公司、研究机构或论坛发布的公告、博客、报告，并生成可读性高的解读摘要。
- `digest-and-notification`: 生成日报或周期性情报简报，并支持主动查询与被动定时通知。

### 修改能力
- 无。

## 影响范围

- 新增 Python 应用骨架、任务调度与 Agent 编排逻辑。
- 集成外部数据源，包括 GitHub API/RSS/网页内容抓取与报告来源配置。
- 新增摘要与报告生成链路，涉及 LLM 调用、提示词模板和结果缓存。
- 新增通知交付能力，第一阶段覆盖邮件和 Webhook，并保留后续扩展其他渠道的适配器接口。
- 需要考虑配置管理、定时任务、失败重试、去重、速率限制和可观测性基础设施。

## ADDED Requirements

### Requirement: 用户可以订阅 GitHub 仓库进行变化追踪
系统 SHALL 允许用户登记一个或多个 GitHub 仓库用于追踪，并配置可调整的回看时间窗口和更新频率。

#### Scenario: 创建仓库订阅
- **WHEN** 用户提交仓库标识和追踪偏好
- **THEN** 系统存储该订阅，并为该仓库安排后续采集任务

#### Scenario: 拒绝无效仓库标识
- **WHEN** 用户提交格式错误或无法访问的仓库标识
- **THEN** 系统拒绝该请求并返回校验错误

### Requirement: 系统从多个 GitHub 信号中采集仓库变化
系统 SHALL 从支持的 GitHub 信号中采集仓库变化，包括发布、已合并的 PR、提交，以及可获取时的相关文档变化。

#### Scenario: 增量采集仓库更新
- **WHEN** 系统为一个已订阅仓库执行定时采集
- **THEN** 系统只抓取自上次成功采集以来新增或发生变化的条目

#### Scenario: 处理临时性的 GitHub 采集失败
- **WHEN** 由于瞬时错误或限流导致 GitHub API 访问失败
- **THEN** 系统记录失败并按退避策略重试，同时不丢失之前的检查点

### Requirement: 系统生成结构化的仓库更新摘要
系统 SHALL 为每个追踪时间窗口生成结构化摘要，并按新增功能、主要改进和问题修复组织内容，同时包含事实变化和简明的价值说明。

#### Scenario: 汇总一个时间窗口内的仓库更新
- **WHEN** 系统在请求的时间窗口内采集到一个或多个仓库变化
- **THEN** 系统生成包含关键变化的摘要，并按新增功能、主要改进和问题修复分组，同时附带来源链接

#### Scenario: 报告没有有效更新
- **WHEN** 请求的时间窗口内没有新的仓库变化
- **THEN** 系统返回“无更新”结果，而不是空白或误导性的摘要

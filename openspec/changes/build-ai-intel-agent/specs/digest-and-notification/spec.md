## ADDED Requirements

### Requirement: 系统生成周期性情报简报
系统 SHALL 生成每日或按计划执行的情报简报，将仓库更新、热门项目分析和报告解读整合为一份连贯摘要。

#### Scenario: 生成定时的每日简报
- **WHEN** 已配置的每日简报计划被触发
- **THEN** 系统使用配置窗口内所有符合条件的内容生成一份简报

#### Scenario: 在上游部分失败时生成简报
- **WHEN** 一个或多个上游采集器失败，但至少有一个内容类别仍有可用结果
- **THEN** 系统仍然生成简报，并将缺失部分标记为不可用

### Requirement: 用户可以主动请求报告和摘要
系统 SHALL 支持用户主动获取仓库摘要、热门分析和简报，而不必等待下一次定时任务。

#### Scenario: 请求按需生成仓库摘要
- **WHEN** 用户请求某个已订阅仓库在受支持时间窗口内的摘要
- **THEN** 系统返回最新可用摘要，或在需要时触发生成

#### Scenario: 请求按需生成简报
- **WHEN** 用户在常规定时任务之外请求一份简报
- **THEN** 系统为指定范围生成或返回对应简报

### Requirement: 系统以 Markdown 和 PDF 格式导出报告
系统 SHALL 允许将生成的简报和摘要导出为 Markdown 和 PDF 文件，以便本地下载或下游分享。

#### Scenario: 将简报导出为 Markdown
- **WHEN** 用户请求把某份已生成简报导出为 Markdown
- **THEN** 系统写出包含简报正文和元数据的 Markdown 文件

#### Scenario: 将简报导出为 PDF
- **WHEN** 用户请求把某份已生成简报导出为 PDF
- **THEN** 系统渲染生成 PDF 文件，并保留章节结构和来源链接

### Requirement: 系统通过已配置的交付渠道发送通知
系统 SHALL 通过已配置的邮件和 Webhook 渠道发送定时或按需报告，并记录投递结果。

#### Scenario: 成功投递一份简报
- **WHEN** 一份简报已准备就绪且存在已配置的通知目标
- **THEN** 系统将该简报发送到目标渠道，并记录一次成功投递事件

#### Scenario: 处理投递失败
- **WHEN** 某个通知渠道返回错误或超时
- **THEN** 系统记录失败，并按渠道策略重试或上报该失败

### Requirement: 系统减少重复通知噪音
系统 SHALL 支持去重和频率控制，避免用户反复收到内容实质相同的通知。

#### Scenario: 抑制重复内容投递
- **WHEN** 在抑制窗口内，同一目标收到两份内容实质相同的简报或提醒负载
- **THEN** 系统抑制重复投递，并记录抑制原因

#### Scenario: 遵守通知频率设置
- **WHEN** 用户配置了通知频率
- **THEN** 系统只按该频率或更低频率发送内容

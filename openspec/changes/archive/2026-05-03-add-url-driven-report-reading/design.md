## Context

当前报告阅读能力主要依赖“预配置来源 -> 批量抓取 -> 生成概览/深读/翻译”这条链路。这个模型适合做常规巡检，但一旦来源站点结构变化、某个栏目未接入、或用户手里已经有一篇具体文章 URL，现有系统就无法继续服务。用户已经明确提出，希望能直接输入任意文章 URL，让系统当场完成正文抓取、解读和全文翻译，从而绕开来源目录覆盖不足的问题。

这个变化会跨越内容抓取、报告分析、缓存复用和 Web 阅读工作台四个层面，因此需要统一设计，而不是只在前端临时加一个输入框。

## Goals / Non-Goals

**Goals:**

- 支持用户手动输入单篇文章 URL，并触发正文抓取、概览生成、深度解读和全文翻译。
- 让手动 URL 导入结果复用现有报告阅读页、详细解读页和导出链路，而不是再造一套平行流程。
- 为 URL 导入建立可复用缓存，避免同一链接重复抓取、重复解读和重复翻译。
- 对抓取失败给出结构化、可展示的失败原因，降低“提交了 URL 但不知道为什么没结果”的挫败感。

**Non-Goals:**

- 不在本次变更中支持整站批量爬取、目录级递归抓取或自动发现同站相关文章。
- 不新增数据库；仍沿用当前本地存储体系。
- 不尝试绕过登录墙、付费墙、机器人校验或明确禁止抓取的访问限制。
- 不在本次变更中扩展为浏览器自动化抓取；优先使用现有 HTTP + 解析链路完成能力闭环。

## Decisions

### 1. 手动 URL 导入复用现有“报告内容项”主模型

手动导入的文章不单独维护一套阅读模型，而是归一为与现有报告条目兼容的内容项结构。这样做的原因是当前系统已经具备最近报告列表、详细页、深读生成、全文翻译和导出流程，如果另建一套 `manual_url_article` 专用渲染链路，会导致状态分裂和维护成本翻倍。

备选方案是为 URL 文章建立完全独立的数据结构和页面路由。这个方案隔离性更强，但会造成前端重复实现“概览、深读、翻译、导出、状态管理”，不符合当前项目追求低复杂度的方向，因此不采用。

### 2. 引入 URL 规范化与缓存键，按“同一文章”复用已有结果

系统在抓取前先做 URL 规范化，至少统一协议、移除明显无业务意义的查询参数和片段，并以规范化 URL 作为缓存命中主键。这样可避免同一篇文章因为分享参数不同被重复落库和重复分析。

备选方案是完全按原始 URL 保存，不做规范化。这样实现简单，但会显著增加重复结果，尤其是带 `utm_*`、锚点或语言参数差异的链接，因此不采用。

### 3. 抓取失败必须返回结构化错误，而不是空结果

URL 导入比来源抓取更偏“用户显式操作”，因此失败反馈必须更具体。系统需要区分至少几类失败：URL 非法、网络访问失败、页面被拒绝访问、正文解析为空、正文过短不适合解读、AI 解读生成失败。Web 端应直接展示这些原因，并保留重试入口。

备选方案是沿用当前“无结果/跳过”风格。这对后台批处理还能接受，但对用户主动贴入 URL 的体验太差，因此不采用。

### 4. 手动 URL 导入只新增入口，不新增独立阅读页

Web 工作台增加“粘贴 URL 立即阅读”的入口，提交成功后直接跳转到现有单篇阅读视图，保持交互一致性。用户无需理解“这是来源抓取的文章还是手动导入的文章”，只需进入统一阅读页。

备选方案是在工作台内内嵌第二套预览区。它可以减少页面切换，但会让长篇深读和全文翻译挤在同一页，阅读体验更差，因此不采用。

### 5. 概览、深读、全文翻译按层次生成，并允许复用已有结果

URL 导入成功后，系统先保证有可读正文，再生成概览摘要。深度解读和全文翻译沿用现有“按需生成但可持久化复用”的模式：如果已有结果则直接复用，没有才生成。这样既能控制首次等待时间，也符合用户之前已经确认的“长内容按需点开”的阅读偏好。

备选方案是导入后立刻同时生成概览、深读和全文翻译。虽然一步到位，但首屏等待会显著变长，也更容易因为单个步骤失败而拖垮整体体验，因此不采用。

## Risks / Trade-offs

- [部分站点正文抽取不稳定] → 先提供 URL 兜底入口，但不承诺所有页面结构都能稳定解析；同时记录结构化失败原因，便于后续针对高频站点修复。
- [URL 规范化过度可能误伤多语言页面] → 规范化阶段只移除明显追踪参数，不主动去掉语言路径或核心查询参数。
- [首次导入长文时等待时间较长] → 采用“先抓正文和概览，深读/全文翻译按需生成”的分层策略，并在前端展示清晰进度。
- [同一文章可能被来源抓取和手动导入重复收录] → 存储层优先以规范化 URL 去重，若已有同 URL 条目则直接复用现有内容和分析结果。

## Migration Plan

1. 在报告采集层增加 URL 导入入口、URL 规范化和正文提取能力。
2. 在报告分析层接入手动导入文章，使其可复用概览、深读、全文翻译和导出链路。
3. 在 Web 报告工作台增加 URL 输入入口、状态提示和跳转逻辑。
4. 为失败场景补充测试，包括非法 URL、正文为空、重复 URL 命中缓存和成功跳转阅读页。
5. 保持原有来源抓取能力不变；若 URL 导入功能出现问题，可只隐藏该入口，不影响既有工作流。

## Open Questions

- 是否需要在后续版本支持用户手动指定“这是一篇英文文章，强制生成中文全文翻译”的快捷选项，还是默认始终尝试全文翻译即可。
- 对于极长网页，全文翻译是否需要引入分段翻译和分段缓存，以降低单次模型调用失败概率。
- 是否要在后续版本中记录“用户手动导入历史”，方便快速重开之前读过的 URL。

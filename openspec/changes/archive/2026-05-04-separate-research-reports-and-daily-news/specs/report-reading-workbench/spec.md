## MODIFIED Requirements

### Requirement: Web 报告页 SHALL 使用卡片化工作台展示最近报告
Web 报告页 MUST 使用非表格化的卡片工作台展示最近报告。每条报告 MUST 以独立卡片呈现标题、来源、发布时间、概览摘要、状态和主要操作入口。

#### Scenario: 最近报告不再以表格主视图呈现
- **WHEN** 用户打开 Web 报告页的“最近报告”区域
- **THEN** 系统 MUST 以卡片化布局展示报告列表
- **THEN** 主视图 MUST NOT 以 `st.dataframe` 形式直接呈现报告集合

#### Scenario: 报告卡片展示关键概览信息
- **WHEN** 用户浏览某一条报告卡片
- **THEN** 卡片 MUST 展示标题、来源、发布时间和概览摘要
- **THEN** 卡片 MUST 提供查看链接或进入详细动作的入口

## ADDED Requirements

### Requirement: Web 报告工作台 SHALL 区分调查报告与每日新闻
Web 报告工作台 MUST 将长篇调查报告阅读和每日新闻流显式分离展示，避免两类内容混在同一主视图中。

#### Scenario: 用户浏览不同内容类型
- **WHEN** 用户在 Web 端查看调查报告与每日新闻
- **THEN** 页面 MUST 让两类内容位于不同区域、不同页签或同等明确的分层结构中
- **THEN** 用户 MUST 能一眼分辨当前看到的是长文调查报告还是快讯新闻

### Requirement: 调查报告阅读页 SHALL 展示正文完整性与失败原因
调查报告阅读页 MUST 展示当前正文是否已完整获取，以及在无法完整读取时的失败原因或限制说明。

#### Scenario: 调查报告正文完整
- **WHEN** 用户打开一篇正文已完整获取的调查报告
- **THEN** 页面 MUST 呈现正文可完整阅读的状态

#### Scenario: 调查报告正文不完整
- **WHEN** 用户打开一篇正文状态为部分正文、站点限制或抓取失败的调查报告
- **THEN** 页面 MUST 显示明确状态与原因说明
- **THEN** 页面 MUST NOT 假装该报告已经完整可读

### Requirement: 调查报告工作台 SHALL 提供正文重抓入口
当调查报告命中旧缓存正文、低质量正文或部分正文时，工作台或详细阅读页 MUST 提供重新抓取正文的入口。

#### Scenario: 用户主动刷新原文正文
- **WHEN** 用户点击重新抓取正文入口
- **THEN** 系统 MUST 尝试重新获取正文
- **THEN** 成功时 MUST 刷新页面中的正文状态和内容

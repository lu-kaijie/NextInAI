## Context

当前项目里的“报告”本质上承担了三种不同职责：公司/研究组织的长文调查报告阅读、普通新闻/博客文章浏览、以及手动 URL 兜底导入。这导致现有实现难以同时满足“快讯浏览”和“长文带读”两类目标。用户最近的实际反馈已经证明，当前最大痛点不是“有没有入口”，而是“读到的正文是不是完整的、格式是不是还能看、失败时能不能说清楚原因”。

从实测结果看：
- Anthropic Research 页面当前网络可达，返回 `200`，说明 `project-vend-2` 和 `constitutional-classifiers` 这类链接的问题更偏向正文抽取质量、旧缓存截断和整篇翻译链路，而不是网站不可达。
- OpenAI 的 `https://openai.com/index/where-the-goblins-came-from/` 当前直连返回 `403`，说明这一类页面至少在当前环境下受到站点访问限制，不能继续当作普通抽取失败处理。

因此，这次设计既要改信息架构，也要改内容完整性判断模型。

## Goals / Non-Goals

**Goals:**

- 把产品显式拆成“调查报告”和“每日新闻”两条体验路径。
- 为调查报告建立“全文是否拿全”的判断能力，并把该状态暴露给前端和后续解读链路。
- 尽可能提升长文正文抽取质量，降低脚本污染、旧缓存截断和整篇翻译被截半的问题。
- 对每日新闻提供主动展示的默认流视图，每条只展示标题、来源和总结，适合快速浏览。
- 对受限站点给出明确失败原因，不让用户继续猜“到底是网络问题还是网站不让抓”。

**Non-Goals:**

- 不在本次变更中引入数据库或多用户系统。
- 不保证所有站点都能完整拿到全文，尤其是不尝试绕过明确的访问限制、登录墙或反爬策略。
- 不在本次变更中实现大规模通用爬虫或浏览器自动化全站抓取。
- 不把每日新闻做成超长深读内容；新闻流仍以快讯浏览为主。

## Decisions

### 1. 产品层面拆成“调查报告”与“每日新闻”

调查报告和每日新闻服务的是两种完全不同的阅读任务。前者强调长文、完整性、逐段理解和后续深读；后者强调主动展现、信息密度和低门槛浏览。因此不再继续沿用一个统一“报告”主视图，而是让调查报告工作台负责长文阅读、每日新闻流负责主动快讯。

备选方案是继续共用一个列表，只靠过滤器区分。这会让默认体验仍然混杂，不利于用户形成稳定预期，因此不采用。

### 2. 为长文引入“正文完整性状态”

系统需要显式判断正文状态，而不是只看 `body_text` 是否非空。建议至少区分：
- `full`: 已拿到足够完整且结构合理的正文
- `partial`: 只拿到部分正文、截断正文或低质量正文
- `restricted`: 页面可达但被站点限制，无法直接读取正文
- `failed`: 网络或解析失败

后续详细解读、全文翻译和 UI 提示都依赖这个状态。没有这个状态，系统只能靠零散规则推断，容易继续误导用户。

### 3. 旧缓存正文需要可判定、可重抓

历史缓存里已经存在大量被旧逻辑截成 `4000` 或 `12000` 字符的正文。继续命中这类缓存会持续污染体验。因此手动 URL 导入和详细页刷新操作都应允许检测“疑似旧截断正文”并重新抓取。

备选方案是要求用户手动清理数据目录。这对个人工具也过于粗糙，因此不采用。

### 4. 全文翻译改为分段整篇翻译

当前“全文翻译”名义上是全文，但底层仍把正文按固定前缀截断后送模型，天然只能翻译半篇。新方案应按段落分块，将整篇正文分多轮送入模型，再拼接成完整翻译结果，并尽量保留段落结构。

备选方案是继续单次调用但简单扩大截断上限。这样会继续受模型上下文、网络稳定性和单次失败概率影响，不够稳，因此不采用。

### 5. 受限站点要单独标注原因

对于像 OpenAI 某些页面这种当前返回 `403` 的情况，系统应明确标注为站点限制，而不是简单归为“没抓到正文”。这不只是错误文案问题，也关系到后续是否继续重试、是否允许生成深读和是否值得提示用户换来源。

## Risks / Trade-offs

- [长文抽取质量仍受页面结构影响] → 用正文完整性状态和失败原因把“不确定性”显式暴露出来，不把脏结果伪装成完整结果。
- [分段整篇翻译会增加模型调用次数和耗时] → 将全文翻译保持按需生成和缓存复用，而不是默认对所有文章批量翻译。
- [新闻流来源扩展后噪声可能增加] → 对新闻流卡片保持极简字段，只展示标题、来源、总结，后续再增加筛选而不是一开始塞太多信息。
- [调查报告与新闻流拆开后实现面变大] → 复用现有内容存储和 agent 分析接口，优先拆展示与状态模型，不重复造轮子。

## Migration Plan

1. 先为长文内容引入正文完整性判断和旧缓存重抓逻辑。
2. 将全文翻译升级为分段整篇翻译，并缓存结果。
3. 在 Web 端拆出“调查报告”与“每日新闻”两个主视图或子区域。
4. 为新闻流引入独立来源分组和默认主动展示。
5. 对受限站点补充原因展示，并阻断不可靠的详细解读生成。

## Open Questions

- 每日新闻的默认来源第一版具体是否只覆盖 AI 公司官网、Hugging Face / LangChain 等平台博客、LessWrong / Latent Space / Simon Willison 这类社区，还是还要纳入更偏媒体的新闻站点。
- 每日新闻流的默认时间口径是“当天”还是“最近 24 小时”，以及首页默认展示多少条最合适。
- 对于调查报告，是否需要在后续版本中提供“正文完整性评分”或“证据等级”，而不只是 `full/partial/restricted/failed` 四类状态。

## ADDED Requirements

### Requirement: 系统 SHALL 提供扩展后的默认报告来源目录
系统 MUST 提供比当前更完整的默认 AI 报告来源目录，覆盖 AI 公司、研究组织、开源平台和高价值社区。来源目录 MUST 至少包含来源名称、分组、抓取地址、来源类型和是否默认启用等元数据。

#### Scenario: 默认来源目录可用于初始化展示
- **WHEN** Web 端请求报告来源列表
- **THEN** 系统 MUST 返回扩展后的默认来源目录
- **THEN** 每个来源 MUST 包含可展示的来源名称和所属分组

#### Scenario: 来源目录覆盖多类主体
- **WHEN** 系统初始化默认来源集合
- **THEN** 默认来源 MUST 同时包含公司类来源和社区类来源
- **THEN** 系统 MUST NOT 只保留单一类型来源

### Requirement: 系统 SHALL 按分组组织报告来源
系统 MUST 支持按来源分组组织报告来源，使用户能够区分公司公告、研究博客、平台更新和社区讨论等不同类型的输入源。分组信息 MUST 可被 Web 报告页直接消费。

#### Scenario: 来源分组可用于前端展示
- **WHEN** Web 报告页展示来源目录
- **THEN** 系统 MUST 返回每个来源所属的分组标签
- **THEN** 前端 MUST 能按分组展示来源，而不需要猜测来源类型

#### Scenario: 默认抓取入口仍可工作
- **WHEN** 用户点击“抓取默认来源组”
- **THEN** 系统 MUST 能依据默认启用标记选出需要抓取的来源
- **THEN** 新的分组结构 MUST NOT 破坏现有快捷抓取体验

### Requirement: 系统 SHALL 支持按来源或来源分组筛选报告
系统 MUST 允许上层界面基于单个来源或来源分组筛选最近报告，以支持用户只看某家公司、某类社区或全部来源的内容。

#### Scenario: 按单个来源筛选
- **WHEN** 用户在 Web 报告页选择某一个具体来源
- **THEN** 系统 MUST 仅返回该来源的报告概览列表

#### Scenario: 按来源分组筛选
- **WHEN** 用户在 Web 报告页选择某一个来源分组
- **THEN** 系统 MUST 仅返回属于该分组的报告概览列表

## ADDED Requirements

### Requirement: 系统识别指定时间窗口内热门的 GitHub 项目
系统 SHALL 使用明确的榜单口径或基于 GitHub 官方 Trending 页面，为指定日期或时间窗口生成 GitHub 热门项目排行榜。

#### Scenario: 生成每日热门项目列表
- **WHEN** 系统执行每日热门分析任务
- **THEN** 系统产出当天热门 GitHub 仓库的前 N 名排行列表

#### Scenario: 生成自定义时间范围的热门项目
- **WHEN** 用户请求一个受支持的自定义时间窗口的热门分析
- **THEN** 系统使用相同的排序策略返回该时间窗口内的结果

### Requirement: 系统解释每个热门项目是做什么的
系统 SHALL 为每个热门仓库生成简短的项目画像，包含其用途、可能面向的人群，以及它值得关注的主要原因。

#### Scenario: 基于仓库元数据生成项目画像
- **WHEN** 一个热门仓库被选中进行分析
- **THEN** 系统提取仓库元数据，并生成对项目的通俗描述

#### Scenario: 在项目解释中保留来源归因
- **WHEN** 系统返回某个热门项目的解释
- **THEN** 返回结果包含该仓库及支撑元数据的链接或引用

### Requirement: 系统解释项目为什么会热门
系统 SHALL 基于可获得的信号给出有依据的热门原因解释，例如近期活跃度、发布事件、star 增长或社区关注。

#### Scenario: 解释热度驱动因素
- **WHEN** 某个项目被纳入热门结果
- **THEN** 系统返回对其热度来源的简明解释，说明哪些信号可能促成了它上榜

#### Scenario: 在热度证据不完整时稳妥降级
- **WHEN** 排名数据可用但支撑证据不完整
- **THEN** 系统将解释标记为部分结论，而不是编造没有依据的原因

## ADDED Requirements

### Requirement: 系统提供常驻对话式 agent 入口
系统 SHALL 提供一个常驻会话式入口，使用户可以通过自然语言查询情报、继续追问、生成简报并执行动作。

#### Scenario: 用户查询最近值得看的内容
- **WHEN** 用户询问“最近最值得看的项目/报告/变化”
- **THEN** 系统识别查询意图，调用相应工具并返回按优先级组织的结果

#### Scenario: 用户继续追问上一轮结果
- **WHEN** 用户基于上一轮回答说“第 3 个详细讲讲”或“刚才那篇报告继续展开”
- **THEN** 系统应使用会话状态解析引用对象，并围绕该对象继续回答

### Requirement: 系统以受控工具编排而非开放式自由代理执行动作
系统 SHALL 使用受控工作流对用户输入进行意图识别、工具选择和执行，并对存在副作用的动作增加确认步骤。

#### Scenario: 查询类请求直接执行
- **WHEN** 用户发起查询、解释或生成预览等无副作用请求
- **THEN** 系统可以直接执行相应工具链路并返回结果

#### Scenario: 外发或修改状态动作需要确认
- **WHEN** 用户要求发送邮件、发送 webhook、创建定时任务或修改订阅
- **THEN** 系统应先向用户确认关键目标或参数，再执行动作

### Requirement: 系统记录每次对话运行的执行轨迹
系统 SHALL 为每次对话运行记录输入、意图、工具调用、输出和错误，以支撑调试、回放和可观测性。

#### Scenario: 一次对话触发多个工具
- **WHEN** 用户请求需要先查询再生成简报或再发送通知
- **THEN** 系统应在同一次 `AgentRun` 中记录完整工具调用序列和最终产出

#### Scenario: 执行过程出现错误
- **WHEN** 工具执行失败、解析引用失败或用户未确认副作用动作
- **THEN** 系统应记录错误和中断原因，并向用户返回清晰状态

# on-demand-deep-report-reading

## Purpose
定义调查报告详细解读的按需生成、缓存复用与阅读导出行为。

## Requirements

### Requirement: 系统 SHALL 按需生成单篇报告的专家带读式深度解读
系统 MUST 支持用户对单篇报告显式触发“专家带读式”深度解读生成。该解读 MUST 明显长于概览摘要，并以逐段说明、解析、评论和保留判断为核心结构，而不是泛泛总结。

#### Scenario: 用户主动生成深度带读
- **WHEN** 用户在某一篇报告上点击“生成详细解读”或同等入口
- **THEN** 系统 MUST 对该报告启动单篇深度解读生成
- **THEN** 生成结果 MUST 聚焦该篇报告，而不是返回泛化的来源级摘要

#### Scenario: 深度带读内容具备结构化讲解
- **WHEN** 系统生成单篇深度解读
- **THEN** 输出 MUST 包含对报告核心问题、关键观点或关键段落的分段讲解
- **THEN** 输出 MUST 包含解释性评论，而不仅是事实罗列

### Requirement: 系统 SHALL 不对所有报告默认预生成深度带读
系统 MUST 将深度带读定义为按需能力，而不是默认在抓取阶段对所有报告批量生成。抓取后的默认分析结果仅作为概览层信息来源。

#### Scenario: 抓取完成后仅有概览层结果
- **WHEN** 用户刚完成一次报告抓取
- **THEN** 系统 MAY 已有概览摘要
- **THEN** 系统 MUST NOT 强制为全部新报告自动生成长篇深度带读

#### Scenario: 只有显式请求才生成深读
- **WHEN** 用户从未点击某篇报告的深读入口
- **THEN** 系统 MUST 允许该报告保持“未生成深读”状态

### Requirement: 深度带读结果 SHALL 被持久化并可复用
系统 MUST 持久化保存单篇报告的深度带读结果，使用户再次查看同一篇报告时可以直接复用已有结果，而不是每次重复生成。

#### Scenario: 用户再次打开已生成过深读的报告
- **WHEN** 某篇报告已经存在可用的深度带读结果
- **THEN** 系统 MUST 直接返回已保存的深读内容
- **THEN** 页面 MUST 告知用户该内容已存在或可直接查看

### Requirement: 系统 SHALL 支持导出单篇深度带读结果
系统 MUST 支持将某一篇报告的深度带读结果导出为 Markdown 和 PDF。导出内容 MUST 对齐页面中的深读正文，而不是退化为短摘要。

#### Scenario: 导出深读 Markdown
- **WHEN** 用户对某篇已生成深读的报告执行 Markdown 导出
- **THEN** 系统 MUST 导出包含完整深读正文的 Markdown 文件

#### Scenario: 导出深读 PDF
- **WHEN** 用户对某篇已生成深读的报告执行 PDF 导出
- **THEN** 系统 MUST 导出包含完整深读正文的 PDF 文件
- **THEN** PDF 内容 MUST 对齐深读结构，而不是只包含概览摘要

### Requirement: 系统 SHALL 仅在完整正文可用时生成详细解读
系统 MUST 仅在确认拿到完整正文时允许生成详细解读。对于部分正文、站点限制或抓取失败的情况，系统 MUST 阻止深读生成并明确告知用户原因。

#### Scenario: 正文完整时允许深读
- **WHEN** 某篇调查报告的正文状态为完整可读
- **THEN** 系统 MUST 允许用户触发详细解读

#### Scenario: 正文不完整时阻止深读
- **WHEN** 某篇调查报告的正文状态不是完整可读
- **THEN** 系统 MUST 拒绝生成详细解读
- **THEN** 页面 MUST 明确说明这样做是为了避免误导用户
